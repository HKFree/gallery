# Reference

## Pages and URLs

| URL | Route name | Access | Shows |
| --- | --- | --- | --- |
| `/gal/area/{area}/ap/{ap}/pub/timeline` | `gallery.public.timeline` | everyone | the AP's public photos |
| `/gal/area/{area}/ap/{ap}/priv/timeline` | `gallery.private.timeline` | signed-in users | the AP's documentation photos |
| `/timeline` | `timeline` | everyone | photos of all APs in Userdb |

The grid views (`…/pub`, `…/priv`) are unchanged. The **Mřížka | Časová osa** switch links each
grid to its timeline and back.

### Query parameters

| Parameter | Pages | Values | Effect |
| --- | --- | --- | --- |
| `from` | all timelines | `YYYY-MM` | Start at the newest photo of that month, then go back in time. Invalid values are ignored. |
| `cursor` | all timelines | opaque | Next page; generated by the **Starší** link. |
| `priv` | `/timeline` | `1` | Also include documentation photos. Ignored for guests. |

Requests sent with the header `X-Requested-With: XMLHttpRequest` receive only the HTML of the
next page (month sections and the next **Starší** link), not the whole page. The page's
script uses this to load older photos while you scroll.

### Page behaviour

| Item | Value |
| --- | --- |
| Photos per page | 60 (`Timeline::PER_PAGE`) |
| Order | `sort_at` descending, then `id` descending |
| Month heading | Czech month name and year, e.g. **Květen 2024**, plus the month's total photo count |
| New files indexed per AP timeline page load | at most 200 (`TimelineController::RECONCILE_LIMIT`) |
| Manage controls (dropzone, delete) | AP timelines only, for users with a role in `GALLERY_ADMIN_ROLES` |

## Date resolution

Each photo is placed by the first available of:

| # | Source | Read from | Conditions |
| --- | --- | --- | --- |
| 1 | Taken date | EXIF `DateTimeOriginal`, else `DateTimeDigitized` | JPEG or TIFF; format `YYYY:MM:DD HH:MM:SS`; plausible |
| 2 | Browser date | `File.lastModified`, sent at upload | new uploads only; plausible |
| 3 | File date | modification time of the stored file | always present |

- **Plausible** means from 1 January 1990 up to one day after the current time.
- **Ignored:** EXIF `DateTime` (the last edit time); placeholder values such as
  `0000:00:00 00:00:00`; values that don't round-trip, such as month 13.
- **Not readable by PHP:** PNG, GIF and WebP don't carry EXIF that PHP can read, so they always
  use source 2 or 3.

All dates are stored as wall-clock time in `GALLERY_TIMEZONE`. EXIF values are used as they
are, and timestamps (sources 2 and 3) are converted.

## Configuration

| Variable | Default | Meaning |
| --- | --- | --- |
| `GALLERY_TIMEZONE` | `Europe/Prague` | Timezone for timeline dates and month boundaries (`services.gallery.timezone`). |

PHP extension `exif` is required (`ext-exif` in `composer.json`).

## Command `gallery:index`

```
php artisan gallery:index [--area=ID] [--ap=ID] [--dry-run]
```

Brings the index in line with the files on disk, for every gallery directory on disk and every
gallery that has rows in the index:

- **Adds** image files (`jpg`, `jpeg`, `png`, `gif`, `webp`) that have no row.
- **Removes** rows whose file is gone.
- **Skips** `thumbs/`, trashed files (`_trashed_…`) and other extensions.
- **Leaves alone** rows for existing files, so their dates are not re-read.

| Option | Effect |
| --- | --- |
| `--area=ID` | Only galleries of this area. |
| `--ap=ID` | Only galleries of this AP. |
| `--dry-run` | Write nothing. Also print how the photos that would be added spread across months. |

Output: the number of photos added and removed, and how many of the added ones have an EXIF
taken date. Exit code `0`.

**Schedule:** daily, without overlapping runs (`routes/console.php`). Requires a cron entry for
`php artisan schedule:run`.

## Index table `gallery_images`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | bigint | |
| `area_id`, `ap_id` | unsigned int | |
| `visibility` | string(4) | `pub` or `priv` |
| `filename` | string | as stored on disk |
| `taken_at` | datetime, nullable | source 1 |
| `client_modified_at` | datetime, nullable | source 2 |
| `uploaded_at` | datetime | source 3 |
| `sort_at` | datetime | first non-null of the three; set on save |
| `sort_month` | char(7) | `YYYY-MM` of `sort_at`; set on save |
| `created_at`, `updated_at` | timestamps | |

Indexes:

- unique `(visibility, area_id, ap_id, filename)`
- `(visibility, area_id, ap_id, sort_at, id)`
- `(visibility, sort_at, id)`

## When the index changes

| Event | Effect on the index |
| --- | --- |
| Upload completes | row created; an indexing failure is logged and the upload still succeeds |
| Photo moved to trash | row deleted |
| AP timeline opened (first page) | that gallery reconciled: up to 200 new files added, rows of missing files removed |
| `gallery:index` | all galleries (or the selected ones) reconciled |
